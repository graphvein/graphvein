# Graphvein v0.2.1

<!-- The release workflow uses this file as the release notes of the tag
v0.2.1, so links are absolute. -->

Indexing now sets a soft memory limit by default, so a large repository whose data fits in memory finishes instead of being killed. Small additions to What Graphvein couldn't read and the API section's callers table.

## Indexing

- Every graphvein command sets a soft memory limit for Go's garbage collector: 70% of the cgroup memory limit on Linux or of physical memory, whichever is smaller. Near the limit the collector runs more often instead of letting the heap grow to twice the live data. A `GOMEMLIMIT` value replaces it, and `GOMEMLIMIT=off` disables it ([ADR 0094](https://github.com/graphvein/graphvein/blob/v0.2.1/docs/adr/0094-default-soft-memory-limit.md), [configuration](https://github.com/graphvein/graphvein/blob/v0.2.1/docs/config.md#memory-limit)).
- The large TypeScript monorepo of v0.2.0's known limits, with its vendored folder excluded (about 9,000 files), was killed at a 7 GiB memory cap without `GOMEMLIMIT`. It now finishes within that cap, with the same facts as a run with `GOMEMLIMIT=5GiB` set by hand.

## Web UI and API

- In a project, What Graphvein couldn't read now says when files of a member could not be parsed: the all-members view names each member with unparsed files and how many, a selected member shows its own count. `/api/v0/project` gains the member field `parse_failed` (left out when zero).
- A Drizzle config whose dialect Graphvein does not read is now listed among the refused model sources, with its file and reason: in `refused_sources` of `/api/v0/schema/summary`, on the Schema page shown when no tables are found and in What Graphvein couldn't read.
- API: where the callers table is narrower than 600 px (for example in the detail pane of a 900 px wide window), each row stacks, with Status and Confidence on a second line under the caller. Wider layouts are unchanged.

## Known limits

- The memory limit is soft: a repository whose live data does not fit in the machine's memory can still be killed by the operating system. The whole monorepo above, vendored folder included, still needs more than 7 GB. On Windows and macOS, a memory limit set on the process (a job object or a process limit) is not read; physical memory is the bound.

The full list is in the [changelog](https://github.com/graphvein/graphvein/blob/v0.2.1/CHANGELOG.md). Install, checksums, provenance and the first-run steps for Windows and macOS are unchanged; see the README's [Install](https://github.com/graphvein/graphvein/blob/v0.2.1/README.md#install) section.
