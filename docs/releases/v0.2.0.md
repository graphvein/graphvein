# Graphvein v0.2.0

<!-- The release workflow uses this file as the release notes of the tag
v0.2.0, so links are absolute. -->

Indexes now live outside your repository, the web UI opens on a new Overview page, and the API, Architecture and Schema sections show more in less space. Stores are smaller, and slow parses are retried instead of dropped.

## Where indexes are kept

- `graphvein index` no longer writes a `.graphvein/` folder into your repository. A new index goes to a per-user stores folder, one folder per indexed folder: `%LocalAppData%\graphvein\stores` on Windows, `~/Library/Application Support/graphvein/stores` on macOS and `~/.local/share/graphvein/stores` on Linux (or `$XDG_DATA_HOME/graphvein/stores` when that is set). The first line of `graphvein index` output says where the index is and why ([ADR 0093](https://github.com/graphvein/graphvein/blob/v0.2.0/docs/adr/0093-per-user-store-location.md)).
- New commands: `graphvein store where` shows where an index is kept, `graphvein store move <path> [<folder>]` moves it (it copies, checks the copy, then removes the old files, and asks first unless you pass `--yes`), and `graphvein store list` lists every index Graphvein knows with its folder and size.
- In the web UI, Settings starts with a Storage section, also when nothing is indexed yet: where each index is, its size, Move… and the folder new indexes go to. Adding a folder shows where its index will be kept, and you can change it there.
- `GRAPHVEIN_STORE_DIR` sets the stores folder, for example for scripts and tests ([configuration](https://github.com/graphvein/graphvein/blob/v0.2.0/docs/config.md#workspace-registry)).

## Web UI

- The Overview page is the new home: the repository's parts and libraries, its interfaces, its data, what Graphvein could not read and where to start. The logo takes you back to it, and the sidebar collapses to its icons with a button or `[`.
- API: one summary strip per transport, with the coverage cards behind "Coverage and roots"; a transport with nothing found is shown as a "none found" tab. The endpoint list, the route header and the callers table are quieter: "0 linked" as text, a shared assumption stated once above the callers, and the route's facts on one line. The Flow tab's legend is one strip, with a Legend button for the full legend.
- Architecture shows libraries by default, as a band under the component cards. Selecting a card or a library marks what it uses and what uses it.
- Schema: when no tables are found, the page lists what Graphvein reads, what it does not read yet, and any model source it found but refused to read, with the file and the reason. What Graphvein couldn't read lists those sources too.

## Indexing

- Stores are up to about a third smaller: shared parts of TypeScript and JavaScript expressions are stored once. Memory for deeply nested code now grows with the size of the file, and a very deep file such as a large generated TypeScript union type no longer needs gigabytes.
- A file whose parse runs out of time while other files are parsed is parsed again alone, with a longer deadline. If a file still cannot be parsed, `graphvein index` and the web UI say that the counts are incomplete.
- A production call whose only match is a route mounted from test code is now unmatched, not test-only, when a production route with an unknown prefix could also serve it.
- A temporary file left behind by a killed `graphvein index` run is removed by the next run.
- Re-indexing a Go repository with deeply nested expressions (for example a long chain of selectors) no longer stalls: checking a cached expression took twice as long for every level of nesting.

## Upgrading

- An index you already have in `<folder>/.graphvein/index.db` keeps working where it is; Graphvein never moves it on its own. To move it to the per-user stores folder, run `graphvein store move <folder>`, or use Move… in Settings, Storage. If a folder ends up with two indexes (for example after going back to an older version), every command refuses and names both until you remove one.
- `GRAPHVEIN_SQLITE_PATH` still names the index file, but now only for the folder named on the command line. Other folders in the web UI's workspace open from their own index.
- The extractor version is now `extractors-64`. The first index after upgrading parses every file again to rebuild its cached facts, so it takes as long as a first index.

## Known limits

- Very large TypeScript monorepos can still run out of memory during indexing. On one such repository (about 28,000 files, most of them vendored), excluding the vendored folder in `.graphveinignore` and setting `GOMEMLIMIT=5GiB` let indexing finish within 7 GB of memory; the whole repository still needs more.

The full list is in the [changelog](https://github.com/graphvein/graphvein/blob/v0.2.0/CHANGELOG.md). Install, checksums, provenance and the first-run steps for Windows and macOS are unchanged; see the README's [Install](https://github.com/graphvein/graphvein/blob/v0.2.0/README.md#install) section.
