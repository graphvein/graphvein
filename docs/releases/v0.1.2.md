# Graphvein v0.1.2

<!-- The release workflow uses this file as the release notes of the tag
v0.1.2, so links are absolute. -->

Fixes for Rust and TypeScript reading, a security fix in Try it, and dependency updates.

## Fixed

- Rust files are no longer dropped when their only syntax errors are attributes on struct pattern fields, such as `#[cfg(...)]` before a field in a `match` pattern: rustc accepts these, the grammar does not, and Graphvein now reads the file from a verified second parse. Any other syntax error still leaves the file unread ([ADR 0092](https://github.com/graphvein/graphvein/blob/v0.1.2/docs/adr/0092-rust-pattern-attribute-recovery.md)).
- A `.rs` file with a few raw NUL bytes inside string literals or comments is read as source instead of being skipped as binary.
- `await f<T>(x)` in TypeScript is read as a call of `f`, so the call gets its name and its caller edge.
- The architecture chain view reports a store failure as an error instead of showing an empty chain.

## Security

- The `curl` command copied from Try it now shell-escapes a configured auth header name and prefix, so a configured value cannot run a command when the copied text is pasted into a shell.
- Dependencies are updated, including SQLite 3.54.1 and security fixes in the development-only oracle tooling. govulncheck reports nothing in the `graphvein` binary.

The full list is in the [changelog](https://github.com/graphvein/graphvein/blob/v0.1.2/CHANGELOG.md). Install, checksums, provenance and the first-run steps for Windows and macOS are unchanged; see the README's [Install](https://github.com/graphvein/graphvein/blob/v0.1.2/README.md#install) section.
