# Claim contract: OpenAPI generation

Task T029 (ADR 0081, **Accepted**). Rows `OG-1`..`OG-99` are reserved for
this table; the rows below are implemented by `internal/openapi`. The Go
table `openapi.Rows` (`internal/openapi/contract.go`) lists the same rows
in the same order with the same forms, and `TestContractTable` keeps the
two 1:1: every value the generator can write in a listed group (refusal
and conflict reasons, methods, scheme classes, `not_read` fields, auth
attributes, shape states, kinds, schema types, stop reasons, user value
keys and statuses, mount shadowing) is the form of exactly one row, and every row a shape
item names in `x-graphvein.shape.not_standard[].row` exists here.

## What the document is

Graphvein writes an OpenAPI 3.1 document from stored facts only: the
`route` nodes of the HTTP route extractors (Express, FastAPI, Axum,
net/http, chi, gin, Next.js; [route extraction](../../extract/routes.md)),
their stored auth attributes ([auth extraction](../../extract/auth.md)),
their stored request and response shape
([route shape](../../extract/route-shape.md), rows SM-1..SM-29), the
imported specs and their `documents_route` edges
([OpenAPI import](../../extract/openapi.md)), and the repository's
`explorer.path_values` in [`graphvein.yaml`](../../config.md#explorer).
It runs no code, reads no source file again and fetches nothing. A field
no row names is never written (row `D`).

The document states what the code registers, not what a running server
answers. Absence is not a claim: a missing `parameters`, `requestBody`,
`responses` or `security` means "Graphvein did not read it", and the
operation says so in `x-graphvein.not_read` (OG-41), never by an empty
value that OpenAPI would read as "none". Only items of kind `fact` (a
typed declaration the framework enforces at runtime) become standard
OpenAPI fields; every other item stays in `x-graphvein` (OG-76, OG-77).

Imported specs are never merged into a generated document (OG-60). One
function writes the document for the CLI
([`graphvein openapi`](../../cli/openapi.md)), the server
([`GET /api/v0/openapi`](../../cli/serve.md#get-apiv0openapi)) and the
UI download, so all three give the same bytes for one store state.

## Path normalisation agreements (checked against references)

Stored templates follow [route extraction](../../extract/routes.md)
("Exact template normalization"). The generator's corpus check compares
the generated documents' paths and methods with committed references
(the T029 task record (internal) has the counts): FastAPI's own generated
client for full-stack-fastapi-template, the realworld spec for Express,
Axum and gin, gotify's, seerr's, owncast's and langflow's committed specs.
No generated operation contradicts a reference on path or method;
parameter names differ where the code and a hand-written spec differ, and
the code's names are written.

## Validation

Every generated document of the golden fixtures and of the corpus check is
validated against the OpenAPI 3.1 JSON Schema with a pinned validator
(`@seriousme/openapi-schema-validator` 2.11.0, MIT) installed outside the
repository, and every Schema Object in it is compiled as JSON Schema
2020-12 (Ajv); the validator is a test-only oracle, never a dependency of
the binary.
