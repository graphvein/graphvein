# Claim contract: "try it" proxy and API explorer

Task T029 (ADR 0081, **Accepted**). Rows `TI-1`..`TI-49` are the proxy,
its guardrails, the user-confirmed options (certificate pins, CA files,
the system proxy, raised limits, free-form paths, multipart bodies,
following a redirect once, sending without auth), the environment edit
and the base URL suggestions; rows
`OX-1`..`OX-49` are what the explorer shows (owned by the explorer UI
unit). The TI table is final for the backend and implemented by
`internal/server/tryit*.go`, `internal/config/tryit.go` and the egress
purpose `try-it`; `TestTryItContractTable` keeps it 1:1 with the code's
row list (`tryItRows`) and checks that every row names an existing test.
The unused number `TI-49` stays reserved.

Endpoints, payloads and limits are documented in `docs/cli/serve.md`
("Try it"); the configuration in `docs/config.md` ("Try it").

## Proxy and guardrails (TI)

A try-it request is never a URL from the browser. The browser names an
environment, a stored route and one of its path keys, and values; the
server builds the URL and refuses anything a row below does not allow.
Every refusal is an error answer with a code; nothing is sent upstream.
Where Graphvein cannot prove a request safe but the user may have a
reason to send it (an untrusted certificate, a path that is not the
operation's, a missing auth variable), the answer offers a user-confirmed
option instead of a hard refusal: either an edit of the environment's
file through the guarded edit (TI-30, TI-48) or a one-time confirmation
bound to the exact request (TI-9). Nothing is accepted by default.
Session state (the selected environment, production acknowledgements,
"don't ask again" grants, typed auth values, pending confirmations) is
held only in the server process's memory and is gone on restart.

| TI-25 | switching or changing an environment | session state is bound to the environment's key: source, name, member, origin, base path, label, auth configuration, the certificate pins for its origin, the CA file's path and content hash, and `use_system_proxy` (limits are not part of it). | TI-26 | free-form paths | with `free_form: true`, `path` is a literal path relative to the environment's base URL that need not match the operation: any of the eight methods, no `path_values`, the route must exist (it names where the user started; logged as `(free-form)`); it starts with `/`, has no `?` or `#` (query pairs go in `query`), bytes outside the characters of a path segment are percent-encoded and a valid `%XX` is kept, no segment may be `.` or `..` after percent-decoding, and an encoded `/` or `\` (`%2F`, `%5C`, any case) or a `\` is refused, so `..%2f` cannot climb: the request stays on the origin under the base URL. It always needs a one-time confirmation (TI-9); a grant never covers it. Without `free_form`, a path that is not one of the route's path keys is refused (TI-7) | 400 `path_mismatch` (without `free_form`), 400 `invalid_path_value`, 400 `bad_request`, 404 `unknown_operation` |

| TI-28 | WebSocket and HTTP/2 cleartext | `Sec-WebSocket-*` headers are refused for every method ("WebSocket endpoints are not supported in try-it yet"), and so is `HTTP2-Settings`; `Upgrade` is refused by TI-13; the client speaks HTTP/1.1 and HTTP/2 over TLS only, never h2c. Multipart bodies: TI-45 | 400 `not_supported` |
| TI-29 | certificate pinning | a certificate neither trusted (TI-17, TI-42) nor pinned refuses the send, answering in `error.details`: `environment`, `origin`, `certificate` (`subject`, `issuer`, `sans`, `not_before`, `not_after`, `sha256`: the SHA-256 of the leaf certificate's DER as 64 lower-case hex characters (the same value `openssl x509 -noout -fingerprint -sha256` prints as upper-case pairs separated by colons, the form the Explorer shows, OX-28); `self_signed`), `reason` and `pinned_sha256`. The user may pin it through the options edit (TI-48): `tls: {pinned_sha256: [...]}`; a pin is bound to one origin (in a repository environment its one origin; in a project environment, which has a base URL per member, each pin is written `{origin, sha256}` and must name one of its base URLs' origins). The egress client then accepts exactly a leaf pinned for that origin whatever its names, issuer or validity dates (the handshake still proves the server holds its key); pins add trust and never reject a certificate that verifies. A leaf that neither verifies nor is pinned while pins exist is a changed certificate: refused, never accepted silently | 502 `upstream_certificate_untrusted`; with pins: 502 `upstream_certificate_changed` (the new certificate and the pins) |
| TI-30 | guarded environment edit | `POST /api/v0/tryit/environments` turns a URL typed in the UI into an environment written to `graphvein.yaml` (target `repository`; created with `version: 1` when absent) or, in project mode, to `graphvein-project.yaml` (target `project`: a new project environment, or the member's base URL in an existing one, keeping its label and auth); as the manifest edit (ADR 0075): a preview with the unified diff and validation, `base_hash` of the file the edit was made on (`absent` for none), a write only with `apply` and the preview's `result_hash`, the session token and loopback peer, an atomic replace; auth names a header and a variable, never a value. Options of an existing environment: TI-48 | 409 `file_changed`, 409 `preview_changed`, 422 `invalid_config` (nothing written), 409 `environment_exists` (a project environment with another label or auth), 409 `no_checkout`, 400 |

| TI-32 | suggestion: Traefik router host | a stored `traefik_routers` entry whose rule is exactly ``Host(`h`)`` (optionally `&& PathPrefix(...)`) gives `https://h` when `tls` is true or a cert resolver is set, else `http://h` | other rules, interpolated routers: none |
| TI-33 | suggestion: committed spec server | a stored `api_spec`'s `servers[].url` that is a valid base URL without templates | templated or relative servers: none |
| TI-34 | suggestion: Dockerfile EXPOSE | a stored Dockerfile stage's `EXPOSE` TCP port gives `http://127.0.0.1:<port>`, file and the stage's `FROM` line, with the reason that a container port is reachable only when published | UDP, interpolated: none |
| TI-35 | suggestion: a member's address of this member | project mode: the addresses `graphvein project suggest` matched to this member as provider (env file URLs, dev-server proxies, define constants of another member), as their origin, with the consumer's file and line | Compose service-name addresses and unmatched addresses: none |

| TI-37 | suggestion: uvicorn.run(port=) literal | an indexed Python line with `uvicorn.run(` and `port=<int>` on the same line | multi-line calls, test files: none |
| TI-38 | suggestion: Go listen address literal | an indexed Go line with `ListenAndServe(":<port>"`, `ListenAndServeTLS(...)` (https) or `.Run(":<port>")` | `_test.go`, addresses in variables: none |
| TI-39 | suggestion: package.json script port | an indexed `package.json` script with `--port <n>`, `--port=<n>` or `-p <n>`, with the script's line | none otherwise |
| TI-40 | suggestion: Procfile port | an indexed `Procfile` line with `--port`/`-p <n>` or `--bind`/`-b <host>:<n>` | none otherwise |
| TI-41 | suggestion: framework default | for production routes of FastAPI (8000), Express (3000, a convention: Express has none), Next.js (3000) and gin (8080): `http://127.0.0.1:<port>`, labelled "framework default, not read from your code", no file | Axum, chi, net/http and other frameworks have no default: none |
| TI-42 | CA file | `tls: {ca_file: <path>}`: a PEM bundle (for example mkcert's root) trusted in addition to the system roots for that environment only; the path is relative to the directory of the file that configures it (the repository root; the project directory for the manifest) or absolute, and is read for every request that resolves the environment: a regular file of at most 4 MiB, read within the environment's time limit; its content hash is part of the environment's key (TI-25), so a changed bundle needs a new selection and the send uses exactly the bytes the key was made from | the file missing, not a regular file, unreadable, too large, too slow to read or without a PEM certificate: 409 `ca_file_error` naming it; a certificate from another CA: TI-29 |
| TI-43 | system proxy | `use_system_proxy: true` (default false): a send to that environment goes through the proxy `HTTPS_PROXY` / `https_proxy` (https) or `HTTP_PROXY` / `http_proxy` (http) names, unless `NO_PROXY` / `no_proxy` matches (`*`, an IP, a CIDR range, a domain and its subdomains, `.domain` for subdomains only, each with an optional `:port`); `localhost` and loopback addresses are never proxied; the variables are read at each send; a value without a scheme is `http://`; schemes `http`, `https`, `socks5`, `socks5h`. The proxy's host and port join that send's egress policy (purpose `try-it`), and the client refuses any request whose destination is not the environment's origin. An `https` proxy's TLS is made apart from the origin's: verified against the system roots for the proxy's own name; the environment's pins and CA file never apply to it. `prepare` names the proxy (scheme, host and port, never user info) and sets `proxy_cleartext` for an `http://` environment, whose whole request, headers and auth value included, passes the proxy in clear | an unusable proxy value: 409 `invalid_proxy`; the proxy's TLS failing: 502 `proxy_tls_error`; another destination: `destination_blocked` |
| TI-44 | per-environment limits | `limits: {request_bytes, response_bytes, timeout_seconds}`, each optional and 1 to its ceiling (64 MiB, 256 MiB, 600 s; defaults 1 MiB, 4 MiB, 30 s); the listing shows each environment's `options` and `effective_limits`, and `limit_ceilings`; a body over the limit, a cut response and a timeout name the limit, its value, its ceiling and how to raise it (`details`, `truncated_limit`) | a value outside 1..ceiling: a config error with file and line (400 in the edit); 413 `body_too_large` |
| TI-45 | multipart form bodies | `multipart: [{name, value \| data_base64, filename, content_type}]` (at most 128 parts; replaces `body` and `content_type`): the server builds a `multipart/form-data` body whose boundary is derived from the content, so prepare and send build the same bytes and the confirmation binds them; a part with `filename` is a file (default type `application/octet-stream`); the body counts against `request_bytes`; `prepare` lists each part's name, file name, content type and size; contents are never logged or returned | 400 `bad_request` (no name, neither or both of `value` and `data_base64`, invalid base64, a line break in a name, with `body` or `content_type`), 413 `body_too_large` |
| TI-46 | following a redirect once | for a 301, 302, 303, 307 or 308 with an http(s) `Location`, `redirect_follow` gives the target (resolved, without user info or fragment), its origin, whether it is the same origin, the method a browser would use (303, and POST on 301/302, become GET; 307 and 308 keep method and body), and either the environment of this repository whose base URL holds the target (longest base path) with the path relative to it, or a suggested environment (`name`, `base_url`: the target's origin) to add through TI-30; the user then selects it and sends the target as a free-form request (TI-26) with its own confirmation and the new environment's production rules. Nothing is followed automatically | - |
| TI-47 | sending without auth | when the environment's `auth.env` is unset or empty and no TI-12 value is held, `prepare` answers `auth_missing: {header, env}` and issues no confirmation; the request is sent without the auth header only with `send_without_auth: true`, GET and HEAD included, bound into the confirmation hash; the choice is refused while auth is available | without the choice: 400 `auth_missing` (details: `header`, `env`); the choice with auth available: 400 `bad_request` |
| TI-48 | environment options edit | `POST /api/v0/tryit/environments` with `options: {name, tls, use_system_proxy, limits}` instead of `environment` replaces those keys of the named environment in `graphvein.yaml` or (target `project`) the manifest, through TI-30's preview with diff, `base_hash`, `apply` with `result_hash`, session token, loopback peer and atomic write; pins are `{origin, sha256}` (origin optional in a repository environment, required in a project one), fingerprints normalised to lower-case hex (a `sha256:` prefix, colons and upper case accepted), `ca_file` is a path, limits are within their ceilings; a TLS or proxy change changes the environment's key (TI-25) | 400 `bad_request`, 400 `edit_refused` (no such environment), 409 `file_changed`, 409 `preview_changed`, 422 `invalid_config` |
| TI-D | everything else | refused for sends: raw URLs from the browser (a free-form path is relative to a configured base URL), hosts or origins not configured (they become configured only through TI-30), CRLF and NUL in values, `Host` and framing headers (TI-13), WebSocket and h2c (TI-28), requests to Graphvein's own endpoints from another site (TI-2). Not suggested: Kubernetes Service ports, `.env` `PORT` keys of a single repository, any form above outside its literal shape. Suggestions are never dialable and never used until the user picks one and TI-30 writes it | 400 |

## Explorer (OX)

The Explorer is a sidebar section of its own (`#/explorer`, ADR 0081
"Explorer UI"): API documentation built from the generated document
(`GET /api/v0/openapi`) and nothing else, with links back to the API
section for callers and impact. It shows only facts the document proves;
every unknown is visible as unknown, and absence is shown only where the
document proves it. Column "Built" says whether the row is shown in this
version (`yes`) or not yet (`pending`); `web/src/sections/explorer/rows.ts`
lists the same rows with the same status and the test that checks each,
and `rows.test.ts` keeps the two 1:1. Labels in the Plain and Technical
styles (ADR 0078) come from rows 59-64 of `web/src/lib/labels.ts`.

Rows OX-20..OX-34 are "Try it out" (T029 part B, the developer's variant
B): a page-wide environment bar, and in each expanded operation a request
builder with the response beside it. Every guard is the server's (rows
TI-*): the UI shows what `prepare` and the refusals say and forwards the
user's answer, so no UI path can send what the server would refuse. Their
labels come from rows 65-68 of `web/src/lib/labels.ts` (a suggestion's
source, where an environment's auth comes from, a confirmation reason, a
cut response). Row OX-35 is a display rule of the operation's sections.

Rows OX-40..OX-43 are the route's shape in the API section's route detail
(T029): the Overview tab's "Request and response" block shows the
endpoint's stored `shape` with the Explorer's section pieces and rules, and
links to the same operation in the Explorer. Row OX-44 is the editor
button on a provenance chip in both places.
