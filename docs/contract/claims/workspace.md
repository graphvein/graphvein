# Claim contract: workspace (multi-index server)

Task T038 ([ADR 0087](../../adr/0087-multi-index-server.md), and the ADR 0041
revision for typed folder paths). Rows `WS-1`..`WS-40` and the default
row `WS-D` are what `graphvein serve` states about the workspace: the
registry, the list of indexes, dispatch by entry, warm indexes and their
answer cache, the background freshness checks, the typed-path flow
that adds a folder and, in rows `WS-70`..`WS-81` (ADR 0093 with ADR 0087
revision 5 and ADR 0041 revision 2), where each index is stored. They are implemented by `internal/workspace` and
`internal/server/workspace*.go`; `TestWorkspaceContractTable` keeps this
table 1:1 with the code's row list (`workspaceRows`), checks that every row
names an existing test, and that every row a refusal carries is in the
table. Rows `WS-41`..`WS-69` are reserved for the web UI's claims; the
The T038 review (ADR 0087 revision 2) took `WS-53` and `WS-54` from that
range for two server rows of the typed-path flow and `WS-55` and `WS-56`
for two web UI rows; revision 3 took `WS-57` (server) and `WS-58` (web UI)
for names shared in one store. The store-location build (T068 part 2)
added the server rows `WS-70`..`WS-81` ("Storage" below); the web UI's
rows stay `WS-41`..`WS-69`.

Endpoints and payloads are documented in
[docs/cli/serve.md](../../cli/serve.md) ("Workspace"); the registry file in
[docs/config.md](../../config.md) ("Workspace registry").

## Registry

| Row | Topic | Rule | Refusal or unknown |
|---|---|---|---|
| WS-1 | registry file | `GRAPHVEIN_WORKSPACE_FILE`, else `workspace.yaml` in the `graphvein` folder of the user configuration directory (`%AppData%` on Windows, `~/Library/Application Support` on macOS, `$XDG_CONFIG_HOME` or `~/.config` elsewhere); a missing file is an empty registry | no configuration directory: the registry is unavailable, `serve <path>` still serves its index and the list reports `registry.error` |
| WS-2 | registry format | YAML `version: 1` and `entries`, each with `kind` (`repository` or `project`), `name`, an absolute `path` and `added_at`; unknown fields refused; the store location is never stored (it is resolved from the folder as the CLI resolves it) | a file that does not parse, another version or an invalid entry is an error on every read and write, and is never rewritten or shown as empty |
| WS-3 | atomic writes | every write reads, changes and replaces the file through a temporary file in the same folder under an exclusive operating-system lock on `workspace.yaml.lock` (`flock` on Linux, macOS and the BSDs, `LockFileEx` on Windows), so writers in two processes never lose an entry; the kernel releases the lock when its holder exits, so the lock file left behind never blocks; reads take no lock | the lock held for more than 10 s: the write fails with "held by another process" and the file is unchanged |
| WS-4 | entry identity | `id` is `<name>~<first 8 hex of SHA-256(kind, NUL, path, NUL, name)>` at registration: the same on every start and in every link (`ws=`); the same name in another folder gets another id; one folder is one entry: adding a folder already registered (also under a new name or kind, as `serve <path>` after a rename does) returns the stored entry and its id; paths are compared as equal strings, or as spellings differing only in letter case that the file system confirms are one folder (`os.SameFile`), so adding one folder spelled two ways on a case-insensitive file system gives one entry | a folder that is gone is compared by its text only |
| WS-5 | folders that are gone | an entry is never dropped by the server or the registry; only remove drops it | - |
| WS-6 | who registers | `serve <path>` and `serve --project` (after their store opened), and add from the UI; `graphvein index` does not | a registry that cannot be written is logged; serving goes on |

## The list: GET /api/v0/workspace

| Row | Topic | Rule | Refusal or unknown |
|---|---|---|---|
| WS-7 | the list | every entry, projects first, then repositories, each by name, then by path; with the session token for the workspace POSTs and the open limit (8) | - |
| WS-8 | entry state | `folder_gone` when the folder is proven missing (any other stat error is not called gone), also while its index is still open; else `open` (its index is open in this server) or `not_open`; the list stats each folder and reads each manifest (and, under a shared store, each `graphvein.yaml`, WS-57), and never opens a store or probes a lock, so it writes nothing into an entry's folder; `name` is the registered one, or while open the one the index serves: the repository `graphvein.yaml` gave as it opened, or the name of the manifest the open project serves (as opened, or as a manifest edit or any request of that project last read it from disk) | - |
| WS-9 | entry freshness | `null` until a background check of the entry or a `GET /api/v0/status` for it (or for a project member) finished, whose answer is recorded at once; only a later check replaces a recorded one; then the states of `GET /api/v0/status` (`fresh` only from a successful zero-change check of a store with runs), with `checked_at` taken before the walk; a project's freshness is folded at each list over the members its manifest lists then, checked at the oldest member's time: `null` while any listed member has no recorded check (a member added since, or one whose listed path is not the path its recorded check was for: an open project checks the paths it opened with until any request of that project reads the edited manifest), otherwise `fresh` only when every member is, `stale` when any member is, `not_indexed` when every member is, else `unknown`; a member without a checkout is `unknown`; a folder that is gone has `null` | never `fresh` from the registry alone, nor over a member nobody checked |
| WS-10 | project members | read from `graphvein-project.yaml` on disk at each list: repository, path, whether the checkout exists, its freshness | a manifest that does not load: `members` null and `members_error` |
| WS-11 | entry job | the entry's latest re-index job of this server process (the `job` of `GET /api/v0/index/run?ws=`) while its index is open, read from memory (no lock probe) | not open: `null` |
| WS-12 | current entry and suggestion | `current` is the entry served without `ws` (the command-line index, or without a path the registered entry whose folder is the working directory); `suggestion` is an unregistered working directory holding `graphvein-project.yaml` or an index the store resolver finds (WS-72) | none: `null` |

## Dispatch and warm indexes

| Row | Topic | Rule | Refusal or unknown |
|---|---|---|---|
| WS-13 | per-index dispatch | every endpoint of a single-index server answers per entry through `ws=<id>`; `ws` is removed before the index's handlers see the request; without `ws` the current entry answers, so single-index URLs keep working | no current entry: 400 `ws_required` |
| WS-14 | ws errors | - | an id the workspace does not have: 404 `unknown_entry` (never another index in its place); `ws` empty or given twice: 400 `bad_request`; a registry that cannot be read: 500 `registry_error` |
| WS-15 | open errors | an entry's index opens read-only on first use, as `serve <path>` or `serve --project` opens it; `POST /api/v0/index/run?ws=` first creates an empty store where `graphvein index` would when there is none, at the place the store resolver gives (WS-70) | no store at the folder: 409 `no_index`, naming the run request and the `graphvein index` command; the folder gone: 409 `folder_gone` (nothing is created), also for an index already open when the request may write (any method but `GET` and `HEAD`); a folder with two indexes or another folder's store folder: 409 `two_indexes` or `foreign_store` (WS-71); its store being moved: 409 `store_moving` (WS-79); a name shared with another folder in one store: 409 `shared_store_conflict` (WS-57); any other open failure: 500 `store_error` |
| WS-16 | open indexes | at most 8 indexes open; beyond that the least recently used index without a request in flight, a running re-index or ref job, and not the command-line index, is closed (its jobs stopped, cache dropped, store closed) | all busy: the limit is exceeded until one is idle |
| WS-17 | answer cache | only `GET` of `/api/v0/api/endpoints`, `/api/v0/precision`, `/api/v0/schema/summary`, `/sets`, `/assumptions`, `/api/v0/architecture` and `/architecture/chain` (views that read only the store and `graphvein.yaml`), keyed by path, query (without `ws`) and the index fingerprint; 200 answers only; `X-Graphvein-Cache: hit`, `miss` or `bypass` | status, freshness, source, file states, editor links and every other path are never cached |
| WS-18 | cache invalidation | the fingerprint is the latest run (count, id, finish time) of the repository or of every member, the content hash of each `graphvein.yaml` and, for a project, the manifest files and the last link pass; a commit by another process, a configuration or manifest edit changes it; the end of this server's run of the index drops the cache, and an answer computed before that is not stored | the fingerprint cannot be read: `bypass` (answered uncached) |
| WS-19 | cache bounds | at most 64 MiB per index and 256 MiB per server, least recently used answers evicted first; an answer over 4 MiB is not cached | - |
| WS-20 | background checks | one check at a time, in its own goroutine: every entry once at start, then every 30 s the open entries and each entry that is not open whose check is missing or older than 2 minutes; an add asks for a pass at once; a folder that is gone, or an entry in a shared-store conflict (WS-57), is not checked and its recorded check is dropped; a check cut short by shutdown records nothing | - |

| WS-37 | add without a run | `"index": false` only registers: 200, `job` null, no store created (except the empty store that records the place "inside the folder", WS-76); `POST /api/v0/index/run?ws=` starts its run later (WS-15) | - |

| WS-D | any other path error | - | an error reading the path that no row covers (for example an invalid name): refused `path_unreadable` with the system's message; a registry that cannot be read during a check: refused `registry_error` |

## Storage (WS-70..WS-81)

Where each index is stored, through the one store resolver of ADR 0093
(`internal/storeloc`): `GRAPHVEIN_POSTGRES_URL`, then
`GRAPHVEIN_SQLITE_PATH` for the command-line folder only, then
`<folder>/.graphvein/index.db`, then a `stores.yaml` entry, then
`<stores>/<name>-<h8>/index.db`. Implemented by
`internal/server/workspace_store.go` and `cmd/graphvein/serve.go`.

| Row | Topic | Rule | Refusal or unknown |
|---|---|---|---|
| WS-70 | each entry's store | every entry's store is resolved by the store resolver; only the index named on `serve`'s command line uses `GRAPHVEIN_SQLITE_PATH`; every other entry opens from its own store, never from that file, and its runs, locks and writer use the place resolved when it opened (never the environment) | - |
| WS-71 | two indexes, foreign store folder | a folder with an index in more than one of its own `.graphvein`, its `stores.yaml` place and the stores folder, or whose store folder's `folder.txt` names another folder, is used by nothing | per-index requests: 409 `two_indexes` or `foreign_store` with both places; a typed path: refused `two_indexes` or `foreign_store`; `GET /api/v0/store`: the entry's `store` with `error_code` and `error` |
| WS-72 | suggestion | the working directory is suggested when the resolver finds an index of it (wherever it is kept) or it holds `graphvein-project.yaml`; nothing is opened or created | an empty `.graphvein` folder is no index: no suggestion |
| WS-73 | store in a check | a `ready` or `registered` check carries `store` (`kind` `sqlite` or `postgres`, `path`, the variable in `env` (never a URL), `origin` (the lookup step), `place` (`inside`, `outside`, `environment`, `postgres`), `exists`, `size` (bytes of `index.db` and `-wal`), `stores_dir` and `dir_source`); a `ready` check carries `places`: the `default` and `inside` index files, `choosable` (false, with `reason`, when the folder has an index already, which stays where it is, or in team mode), and with `store_place` the `chosen` place (and `folder`, the typed folder's index file) | - |
| WS-74 | store place | `store_place` `default`, `inside` (`<folder>/.graphvein/index.db`, where Git lists it unless an ignore file covers it) or `folder` with `store_dir`, for this folder only | another value, `store_dir` without `folder`, `folder` without `store_dir`: 400 `bad_request`; the folder has an index elsewhere: refused `store_fixed`; team mode: refused `team_mode`; a server that cannot create a store: refused `place_unavailable` |
| WS-75 | typed store folders | `store_dir`, a move's `dest_dir` and a `default_dir` are absolute; links resolved in the part that exists; the index goes to `<folder>/<name>-<h8>/index.db` | refused with the row and code: `not_absolute`, `network_path` (a UNC path or a drive Windows reports as remote), `filesystem_root`, `home_directory`, `inside_git`, `inside_folder` (the indexed folder or inside it), `inside_registered` (a workspace folder or inside one), `not_a_directory`, `not_writable`, `unreadable`, `index_exists` (an `index.db` is there already), `foreign_store` (the store folder's `folder.txt` names another folder) |
| WS-76 | add binds the store | the confirm value of a `ready` check is bound to the resolved folder, kind, name, the chosen place and the index file it showed; the add re-checks all of them, then records the place (a `stores.yaml` entry for a typed folder, the removal of one for the default, an empty store for inside) before it registers the entry and starts the run | the index file would now be another: 409 `path_changed` (nothing recorded or registered); a confirm value of a store check: 409 `confirm_required` |
| WS-77 | Storage settings | `GET /api/v0/store` needs no index and opens no store: `team_mode` (set, never the URL), `sqlite_path` (set, and the command-line entry it applies to), `default_dir` (path, `source` `platform`, `env` or `stores_file`, `editable` with a `reason` when `GRAPHVEIN_STORE_DIR` or team mode decides), the `stores.yaml` and registry paths, and per entry its folder, whether the folder exists, its `store` (WS-73's fields; null when the folder is gone) and `movable` with a `reason` | a registry that cannot be read: `registry.error`; a `stores.yaml` that does not load: `default_dir.error` and not editable |
| WS-78 | move check | `POST /api/v0/store/check` with `id` and `dest_dir` (`""` for the folder's place in the stores folder) plans the move as `graphvein store move` does and answers `ready` with `move` (folder, `from`, its `from_place`, `to`, `to_default`, `size`), a one-time confirm value bound to the entry, `dest_dir` and both index files (10 minutes), and the equivalent `command` | an unknown entry: 404 `unknown_entry`; refused `team_mode`, `sqlite_path_env` (the command-line index's file from the variable), `no_index`, `folder_gone`, `entry_in_use` (the command-line index of a server that cannot close it), `same_place`, and WS-75's codes |
| WS-79 | move | `POST /api/v0/store/move` with `id`, `dest_dir` and the confirm value re-plans the move; stops serving the entry (requests answer 409 `store_moving`, background checks skip it), waits for requests in flight (at most 30 s) and closes its index (the command-line index through its owner's close), then moves as `graphvein store move` does (index lock, `VACUUM INTO`, same run ids and row counts, record, delete the old files) and answers the result; the next request opens the index at its new place | a used, expired or another move's confirm value: 409 `confirm_required`; the plan changed: 409 `path_changed`; a re-index or ref job of this server running: 409 `index_running`; requests still reading after 30 s: 409 `index_busy`; another process holding the index lock: 409 `index_locked`; the copy or its check failed: 500 `move_failed`, the original kept; the original's files not all deleted: 200 with `remaining` and `warning` (both stores are then refused, WS-71, until they are deleted) |
| WS-80 | folder for new indexes | `POST /api/v0/store/check` with `default_dir` (`""` for the platform's folder) answers `ready` with the change and a confirm value; `POST /api/v0/store/default` with the same `default_dir` and the value sets `stores.yaml`'s `default_dir`; indexes that exist stay where they are (one in the old folder gets a `stores.yaml` entry) | team mode: refused `team_mode`; `GRAPHVEIN_STORE_DIR` set: refused `set_by_environment`; the same folder: refused `unchanged`; no per-user data folder for `""`: refused `no_platform_folder`; WS-75's codes; the value of another check or folder: 409 `confirm_required`; changed since: 409 `path_changed` |
| WS-81 | runs after a move | an entry's re-index (and a project's member runs and link pass) checks the store's place before and after taking the index lock; a run that waited for the lock while a move finished stops instead of creating a store at the old place | 409 `store_moved` naming both places |

reads only `GET /api/v0/workspace`, the typed-path POSTs and the per-index

existing web test. Rows `WS-53`, `WS-54` and `WS-57` are server rows
(above); `WS-59`..`WS-68` stay free.
