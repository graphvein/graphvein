# Indexer contract v1

This is the authoritative boundary between any indexer and Graphvein. No parser
implementation knowledge is required. See Proposed ADR 0005 for design rationale.

External producers also follow the [executable invocation contract](external-indexer.md).

## Transport and framing

Emit UTF-8 NDJSON to stdout: one JSON object per line, LF terminators including
the final line, no BOM or blank lines. Send logs to stderr. A record must be less
than 8 MiB encoded (excluding LF). Object keys must be unique. Header is first,
footer is last, and EOF must immediately follow the footer LF. Property order
does not matter. All fields below are required unless marked optional.

Every stream is a **complete repository snapshot**, including unchanged files.
Omitted files/nodes/edges are removed when ingestion succeeds. V1 has no delta
or deletion records. `repository` is a stable, caller-configured logical root
identifier shared across checkouts, e.g. `graphvein`, never an absolute path.
The identifier must be nonempty and cannot contain NUL.
Separate repositories are isolated in storage even when identities match.

Emit each file before its nodes and all files/nodes before the first edge.
Diagnostics may appear anywhere between header and footer. Source nodes and
edge evidence must reference files already emitted; endpoints must reference
nodes already emitted. Duplicate graph keys use the last valid record (files:
path; nodes: identity; edges: kind + source + target). A changed duplicate file
removes its previously emitted symbols before replacement. Prefer emitting each
key once. A body error never stops processing another file.

```json
{"type":"header","contract_version":1,"indexer":{"name":"example","version":"0.1"},"repository":"example","generated_at":"2026-10-05T00:00:00Z"}
{"type":"footer","counts":{"records":0,"file":0,"node":0,"edge":0,"diagnostic":0}}
```

`generated_at` is an RFC 3339 timestamp with timezone. Optional `commit` is the
producer's source revision metadata; it never participates in identity/hashing.
An empty snapshot deliberately clears the repository. The footer `records`
counts every body line, including malformed or unknown records. Each typed
count counts lines declaring that `type`, including invalid records of that
type. Neither header/footer nor consumer-generated diagnostics are counted.
Malformed JSON with no readable type contributes only to `records`.

Invalid headers (including unknown contract versions), duplicate headers,
invalid footer/counts, overlong lines, missing LF, trailing records, I/O errors
and missing footer reject the import and roll back the snapshot. Invalid body
records produce line-numbered diagnostics and are skipped. Successful runs
publish in one transaction, buffering at most 128 records per write batch.
Run metadata includes producer header, start/end times and optional commit.

## Paths, identity and spans

Paths use `/`, are relative, case-sensitive and UTF-8. No drive prefixes,
absolute paths, backslashes, empty segments, trailing `/`, `.` or `..` segments,
colon, NUL, CR or LF. Never case-fold or Unicode-normalize paths/names. For
synthetic nodes only, `file: "."` denotes the repository root; omit their span.

Identity is `kind:escaped-path#escaped-qualified-name`. `kind` matches
`[a-z][a-z0-9_]*`. Encode the path and qualified name separately as UTF-8 bytes.
Leave ASCII letters, digits, `-._~` unescaped; also leave `/` unescaped in paths.
Every other byte is `%HH` with uppercase hex. Thus `%` is `%25`, `#` is `%23`,
`:` is `%3A`, a space is `%20`, and `é` is `%C3%A9`. Reject lowercase escapes,
escaped safe bytes, and alternate spellings; decoding then canonical encoding
must reproduce the original identity. Qualified names must be nonempty UTF-8
without NUL. Node identity components must exactly match kind/file/qualified_name.

Qualified names represent lexical owners joined with `.`, preserving their
original spelling. Receiver types belong in method names. Routes include the
HTTP verb and literal route pattern; tables use schema + table. Extractors must
use semantic discriminators for overloads/anonymous declarations, never body
hashes or line numbers. Names and paths changing produces new identity; edits
to a body leave identity intact. L5 location nodes may name a range, making their
identity intentionally sensitive to location changes.

| Example | Identity |
|---|---|
| TypeScript class method | `method:src/user.ts#User.save` |
| Rust impl method | `method:src/user.rs#User.save` |
| Nested Python function | `function:src/jobs.py#run.validate` |
| HTTP route | `route:src/api.ts#GET%20%2Fusers%2F%3Aid` |
| SQL table | `table:migrations/001.sql#public.users` |
| Escaped path/name | `method:src/my%20%23file.ts#C.m%C3%A9thod%3A1` |
| External package | `external:.#npm%3Areact` |

Spans contain `start_line`, `start_column`, `end_line`, `end_column`. Lines are
1-based; columns are 0-based UTF-8 **byte offsets**, not characters or UTF-16
units. End is exclusive. Measure against LF-normalized source. End cannot
precede start. Empty spans are allowed. A source node requires a span. Synthetic
nodes omit spans. V1 cannot check source bounds without the source file.

## Hashes

Hash source bytes using SHA-256 after converting CRLF to LF, then lone CR to LF.
Perform no other transformation: retain tabs, trailing spaces, indentation,
comments, Unicode spelling, BOM bytes and whether a final newline exists.
The representation is `sha256:` + exactly 64 lowercase hex digits.

File hashes cover the whole normalized file. Source node hashes cover the exact
half-open span in that normalized source, including comments/whitespace within
the span. For synthetic nodes hash their semantic `attributes` as canonical JSON:
recursively sort object keys by Unicode code point, retain array order, use no
insignificant whitespace, emit UTF-8 Unicode directly, and emit no final LF.
Synthetic attributes must contain only JSON null, booleans, strings, arrays,
objects and integers in [-9007199254740991, 9007199254740991]; no floats. Escape
quotes, backslashes and control characters using JSON escapes (use `\b`, `\t`,
`\n`, `\f`, `\r`, and lowercase `\u00hh` for the remaining controls); do not
escape `/`, `<`, `>`, `&`, U+2028 or U+2029. Exclude location/commit metadata.

Example: normalized `abc` hashes to
`sha256:ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad`;
empty source hashes to
`sha256:e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`.
V1 deliberately favors safe invalidation over language-dependent whitespace
stripping. A new normalization rule requires a new contract version.

## Records

The accompanying `v1/*.schema.json` files define structural validation; the
canonical identity, reference, path and span rules above add semantic validation.

### File

`type: "file"`, `path`, `language` (nonempty producer language name), `precision`
(`precise` or `best_effort`), `size` (nonnegative original byte count),
`content_hash`; optional `git_blob_oid` is 40 or 64 lowercase hexadecimal digits
for a git SHA-1 or SHA-256 blob. A blob OID does not replace the normalized hash.

### Node

`type: "node"`, `identity`, `kind`, `level` (integer 0–5), `name` (nonempty display
name), `qualified_name`, `file`, `content_hash`, `attributes` (open JSON object),
and `span` for source nodes. Levels: 0 system, 1 component, 2 area, 3 file,
4 symbol, 5 location. Kind vocabulary is extensible lowercase identifiers, e.g.
`system`, `component`, `package`, `file`, `function`, `method`, `class`, `route`,
`table`, `column`, `location`, `external`; levels are explicit, not inferred. A `package` node (level 2, T026, ADR 0079) is one confirmed package manifest; its attributes are listed in [docs/extract/packages.md](../extract/packages.md). FastAPI `route` nodes may carry `security_dependencies` and `security_dependencies_unknown`, and hey-api `client_call` nodes `security` (T026 AG-B4a); Express `route` nodes may carry `mounted_middleware`, `mounted_middleware_unknown` and `middleware_declares`, and Axum `route` nodes `layers` and `layers_unknown` (T026 AG-B4b), and gin and chi `route` nodes `group_middleware` and `group_middleware_unknown` (T029 SH-S, optional attributes, no contract version change) ([docs/extract/auth.md](../extract/auth.md)). Any `route` node may carry `shape`, its request/response shape (model version 1; [docs/extract/route-shape.md](../extract/route-shape.md), claim rows SM-1..SM-29 in [claims/route-shape.md](claims/route-shape.md)); an optional attribute, so no contract version change. A `route` node whose shape uses a model declaration may carry `model_uses` (one entry per declaration, section, status and provenance kind) and has one `uses_model` edge to each such declaration node (T029 W2, rows MT-1..MT-12 in [claims/route-model-types.md](claims/route-model-types.md)); an optional attribute and an extensible edge kind, so no contract version change. A `deploy_service` node (level 2) is one service of one compose file and a `dockerfile` node (level 3) one Dockerfile (T026, ADR 0079); their attributes are listed in [docs/extract/deploy.md](../extract/deploy.md). TypeScript and JavaScript files may carry `renders` (a JSX element of a repository function or class), `passes_function` (a repository function passed as a value) and react-router `ui_route` nodes (`framework: "react-router"`) with `routes_to` and `passes_function` edges (T026, [docs/lang/typescript-bridges.md](../lang/typescript-bridges.md)).

References outside the snapshot require an explicit `external` node with
`file: "."`, no span, and attributes identifying the ecosystem/name. For a
reference whose identity cannot be resolved, emit such a node with
`attributes.unresolved: true` and a diagnostic explaining the limitation. Never
invent a dangling edge. Rationale and caches later bind identity + content_hash.

### Edge

`type: "edge"`, `kind`, `source` and `target` (canonical node identities),
`provenance` (`fact`, `inferred`, `assessment`, `agent_proposed`), `confidence`
(number 0–1; exactly 1 for facts), `evidence` (array, possibly empty, of objects
containing `file` and `span`). Kinds are extensible identifiers, e.g. `contains`,
`imports`, `calls`, `references`, `implements`, `inherits`, `exposes_route`,
`calls_route`, `reads_table`, `writes_table`, `uses_config`, `depends_on_external`.
Kinds Graphvein's own indexer adds within v1 (extensible, no version
change): the server action transport of ADR 0077 (T024b) is the level-4
node kinds `server_action` (one per action) and `action_call` (one per
proven use), and the edge kinds `exposes_action` (implementing function to
action) and `calls_action` (use to action). Supabase migration sets
(T024c1) are `migration` nodes with `tool: supabase` and a `platform`
attribute (T024c1b adds its list `assumptions` of `{id, text}`); their `table` nodes add the attributes `rls` and `policies`, and
a column reference to a platform table has `status: external` (no edge).
Supabase table access (T024c2) uses the existing `reads_table` /
`writes_table` edges; the owner's `table_access` entries add the `tool`
value `supabase` and its `table_access_unknown` entries the reason codes
`table_dynamic`, `client_unproven`, `embedded_resource` and `builder_unread`.
Supabase generated types (T024c3) are model `table` and `column` nodes
(ADR 0058) of tool `supabase_types` with the table attributes `label`,
`types_header`, `package`, `relationships` and `computed_fields`, and the
diagnostic codes `supabase_types_unread`, `supabase_types_compared` and
`supabase_types_disagreement`.
Evidence must refer to emitted source files. Deleting a file removes nodes,
incident edges and any edges using that file as evidence.

### Diagnostic

`type: "diagnostic"`, `file` (relative path or empty for stream/run diagnostics),
`severity` (`info`, `warning`, `error`), `code`, `message` (both nonempty). These
records do not abort ingestion. Consumer validation uses codes `invalid_record`,
`unknown_field` and `invalid_reference`. Messages include wire line numbers.

## Versioning and extensions

`contract_version` is an integer major version. Reject anything other than 1
before beginning an index run. Changes to required fields, identity, hashing,
span semantics, snapshot scope or existing record meaning are breaking changes:
bump version, update documentation, schemas and golden fixtures together.

Unknown fields in known records (including structured nested objects) are
ignored with an `unknown_field` diagnostic per JSON path. Open `attributes`
maps accept arbitrary keys without warnings. Unknown record types are invalid
body records, diagnosed and skipped, but counted in footer `records`. Unknown
fields do not alter graph keys or hashes. Producers may add optional fields;
older consumers report that they ignored them. Contract v1 is first introduced
here; there is no existing contract version or existing contract golden to bump.

## CLI

`graphvein ingest snapshot.ndjson` opens SQLite at `.graphvein/index.db` by
default; `GRAPHVEIN_SQLITE_PATH` overrides it. `GRAPHVEIN_POSTGRES_URL` selects
Postgres instead. Secrets belong in environment variables. Postgres is explicit
infrastructure access and dials only through `internal/egress`. Invalid framing
or storage failures exit 1; usage errors exit 2; a completed import exits 0 even
when body diagnostics were recorded.
