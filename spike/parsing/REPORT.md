# T001 — Parsing measurement report

Measured on 2026-10-05. Recommendation: **Option A, WASM in pure Go**. It parses
both requested languages correctly on Windows, including the arrow-function
`const` case, and cross-builds with only Go. Option B cannot build with the
installed tools, which satisfies T001's fallback decision rule. No speed ratio
against native is claimed.

## Environment and dependencies

- Windows/amd64; `go version go1.27.1 windows/amd64`.
- Commands run through existing `C:/Program Files/Git/bin/bash.exe`.
- `gcc --version`: command not found. Neither `clang` nor `cc` is on Git Bash's PATH.
- Go's default `CGO_ENABLED` is `0`. The runner explicitly enables it for native.
- No system software installed. Downloaded Go modules and pinned grammar assets.
- WASM: `github.com/zema1/wasitter v0.1.0`, `wazero v1.10.1`.
- Native: official `go-tree-sitter v0.25.0`, TypeScript/TSX grammar v0.23.2,
  Rust grammar v0.24.2. WASM release registry specifies the same grammar versions
  and its notices identify the tree-sitter runtime as v0.25.0.

The WASM assets passed the published SHA-256 checksums. Their release registry,
checksums and third-party notices are preserved under `grammars/`. See the
[upstream usage documentation](https://github.com/zema1/wasitter/tree/v0.1.0)
for the version-matched asset and runtime lifecycle requirements.

The workload is synthetic, as allowed by T001: 1,000 blocks with unique
interfaces, type aliases, functions, arrow functions with JSX, and classes.
It is generated by the runner, not copied from an external repository. The test
suite also traverses it and checks that all 3,000 requested declarations appear.

Timing covers the parse call, including its Go wrapper and input copy, with a
reused TSX parser and a fresh tree (`oldTree=nil`) each run. Runtime creation,
WASM compilation, disk I/O, AST traversal, syntax-error inspection and tree
cleanup are outside the timed interval. There is no warm-up parse. All five
trees are checked for syntax errors and closed before the next run. The timings
therefore do not measure complete indexing throughput or cold-start cost.

Binary sizes are default, unstripped Go builds without VCS stamping. WASM assets
are embedded; the native build excludes them. Peak RSS is left unmeasured because
the runner has no portable process-memory probe; Go heap statistics would miss
native allocations and are not a fair substitute. Cross-built binaries have not
been executed on Linux or macOS. Native cross-builds failed before any target C
compiler compatibility could be evaluated.

## Problems and verification

1. The sandbox initially blocked module downloads and the user-cache writes.
   Authorized dependency downloads and a workspace-local `GOCACHE` resolved
   these environment limitations without changing system configuration.
2. Git rejected the checkout owner for VCS stamping. The runner uses
   `-buildvcs=false`; status inspection used a command-local `safe.directory`
   exception. No global Git settings were changed.
3. Native compilation reports missing GCC for Windows/Linux and missing Clang
   for macOS. The native implementation is supplied but cannot be compiled,
   tested, timed or crash-checked on this machine.

`go test ./...` passes from `spike/parsing`, including both goldens, deliberate
wrong-golden rejection, all generated declarations, five-run measurements,
malformed-source recovery, and continuing to Rust after a missing TSX file.
`go vet ./...` passes. The comparison runner completes successfully, recording
the native build limitations. Existing goldens were not changed; these are new,
hand-checked spike expectations. There is no root Go module or pre-existing
golden fixture suite to run; the full suite for this task is in the isolated module.

## Recommendation and limits

Select WASM per T001 because it is correct and cgo needs an extra system
toolchain. Keep parsing in `internal/parse` when M1 implements it. Reuse one
runtime/parser per worker and close trees before parsers and runtimes, following
the upstream lifecycle guidance. The isolated spike does not define production
interfaces or alter the indexer contract.

Follow up with native measurements when a compiler is already available, and
profile cold start, memory, queries, incremental parsing and real corpus files
before choosing worker counts. wasitter is a young wrapper; this experiment
validates only the exercised API and grammar versions, not its full maturity.
